## Executive Summary

CreativeTrust.pl is a well-designed Next.js agency site with solid hosting infrastructure (Netlify/Cloudflare) and active content production (30+ blog posts, 50+ portfolio entries, 35+ glossary definitions). However, it carries a cluster of **foundational technical SEO defects** that are suppressing its visibility across both traditional and AI-powered search. The most critical issue is a self-inflicted AI search blackout caused by Cloudflare-managed robots.txt blocking Google-Extended, GPTBot, and ClaudeBot — rendering the site invisible in AI Overviews and ChatGPT Search despite having exactly the right content type to appear there.

The site also has zero structured data, duplicate `<title>` tags on every page, no canonical tags anywhere, a sitemap that uses the wrong domain (non-www vs. serving domain www), and two of its most commercially valuable pages (/google-ads, /meta-ads) have no custom SEO metadata because they are `"use client"` components.

**Top 5 Critical Issues:**
1. Google-Extended, GPTBot, ClaudeBot blocked in robots.txt → invisible in AI search
2. Duplicate `<title>` tags on every page (hardcoded vs. Next.js Metadata API)
3. No canonical tags on any page + sitemap domain mismatch (non-www URLs)
4. Zero JSON-LD structured data (no Organization, no Article, no FAQPage)
5. /google-ads and /meta-ads are `"use client"` components → no custom metadata rendered

**Top 5 Quick Wins (< 2 hours each):**
1. Unblock Google-Extended in Cloudflare robots.txt → unlocks AI Overviews immediately
2. Remove hardcoded `<title>Creative Trust</title>` from layout.tsx line 129
3. Fix `siteUrl` in next-sitemap.config.js to `https://www.creativetrust.pl`
4. Add `metadataBase` + Organization JSON-LD to root layout
5. Fix placeholder title `'Strony WWW | Twoja Agencja'` on /uslugi/strony-www

## 1. Technical SEO

**Score: 38 / 100**

### C-1 CRITICAL — Sitemap domain mismatch (non-www vs. www)

All 130+ URLs in `sitemap-0.xml` use `https://creativetrust.pl/` (non-www), but the live serving domain is `https://www.creativetrust.pl/`. Google treats these as two distinct origins. Googlebot crawls these non-www URLs and receives 301 redirects to www, wasting crawl budget and splitting ranking signals.

**Root cause:** `next-sitemap.config.js` line 3: `siteUrl: 'https://creativetrust.pl'`  
**Fix:** Change to `'https://www.creativetrust.pl'` and redeploy. Resolves the `robots.txt` `Sitemap:` directive and `Host:` directive simultaneously.

### C-2 CRITICAL — Duplicate `<title>` tag on every page

Every page renders two `<title>` elements in the HTML:
- `<title>Creative Trust</title>` — hardcoded at `layout.tsx:129` inside `<head>`
- `<title>[Page Title]</title>` — generated by Next.js Metadata API

**Root cause:** The `export const metadata` in `layout.tsx` and a manual `<title>` tag coexist. The Next.js App Router Metadata API is the correct mechanism — the manual tag must be removed.  
**Fix:** Delete line 129 from `src/app/layout.tsx`.

### C-3 CRITICAL — No canonical tags on any page

Zero pages have `<link rel="canonical">`. Without canonicals, Google cannot consolidate signals across www/non-www variants, trailing-slash/no-slash variants, and any scraped copies of content.

**Fix:** Add `metadataBase: new URL('https://www.creativetrust.pl')` to root layout metadata. Then add `alternates: { canonical: '/' }` to the root layout and page-specific canonical paths in each page's metadata export.

### C-4 CRITICAL — /google-ads and /meta-ads are "use client" components with no metadata

`src/app/uslugi/performance-marketing/google-ads/page.tsx` and `/meta-ads/page.tsx` both begin with `"use client"`. Next.js App Router cannot process metadata exports from client components. Both pages fall back to the generic layout title `CreativeTrust` and generic description. These are the agency's highest-commercial-intent pages.

**Fix:** Extract all animation/interaction logic into a separate `ClientContent` component marked `"use client"`. Keep the page file as a Server Component and add a `metadata` export with a proper title and description.

### H-1 HIGH — /panel-klienta appears in sitemap despite being excluded

The `next-sitemap.config.js` exclude array contains `/panel-klienta/*` (with wildcard) but not `/panel-klienta` (root path). The built sitemap contains `<loc>https://creativetrust.pl/panel-klienta</loc>`, which responds with a 307 redirect to `/logowanie-klienta`. Google is instructed to index a private client panel redirect.

**Fix:** Add `/panel-klienta` (without wildcard) to the exclude array.

### H-2 HIGH — Missing security headers

Response headers from `curl -I https://www.creativetrust.pl/` show these are absent:
- `Content-Security-Policy` — no XSS mitigation
- `X-Frame-Options` — clickjacking protection absent
- `Permissions-Policy` — no feature control
- `Referrer-Policy` — referrer leakage uncontrolled
- `x-powered-by: Next.js` exposed (minor)

HSTS is present (`max-age=31536000`) but missing `includeSubDomains` and `preload`.

**Fix:** Add via `next.config.ts` `headers()` function or Netlify `_headers` / `netlify.toml`.

### H-3 HIGH — Duplicate GTM + GA4 initialisation and double `gtag` definition

`layout.tsx` inline script both initialises GTM (`GTM-WTKHM3K`) and directly calls `gtag('config', 'G-2PK8VH2GDV')`. If GTM also contains a GA4 tag (standard practice), every pageview is counted twice. Additionally, `gtag` is defined twice within the same script block (lines ~38–40 and ~121–123), silently overwriting the function reference.

**Fix:** Remove the standalone GA4 initialisation from the inline script. GA4 should be managed exclusively through GTM.

### M-1 MEDIUM — userScalable: false in viewport

`layout.tsx` exports `viewport: { maximumScale: 1, userScalable: false }`. This prevents users from zooming on mobile — a WCAG 1.4.4 Level AA accessibility violation and a Google mobile-friendliness flag.

**Fix:** Remove `userScalable: false` and `maximumScale: 1` from the viewport export.

### M-2 MEDIUM — No Open Graph or Twitter Card tags (most pages)

No `og:title`, `og:description`, `og:image`, `og:url`, `twitter:card` on the homepage or any service page. Only blog posts have OG tags (via `generateMetadata`). Social link shares produce unformatted plain-text cards for all service pages.

**Fix:** Add `openGraph` and `twitter` fields to the `metadata` export on all service pages and the homepage.

### M-3 MEDIUM — Hero/LCP images not marked priority

The homepage HTML shows 8 `loading="lazy"` attributes and zero `fetchPriority="high"`. On key landing pages the hero image is preloaded in `<head>` but the `<img>` tag itself does not carry `fetchPriority="high"`.

**Fix:** Add `priority` prop to Next.js `<Image>` components used for above-the-fold hero sections.

### M-4 MEDIUM — Client-side skeleton loaders for above-fold content

The homepage SSR HTML contains `animate-pulse` skeleton placeholders for portfolio cards and blog cards. These populate only after client-side hydration, creating CLS risk and degrading LCP.

**Fix:** Convert these sections to async Server Components with `await sanityClient.fetch(...)` so content is present in initial HTML.

### L-1 LOW — `lastmod` timestamps hardcoded to build time

`next-sitemap.config.js` uses `lastmod: new Date().toISOString()` for all blog/portfolio paths. Every deploy marks all 30+ blog posts as "modified today" regardless of actual content changes.

**Fix:** Replace with `lastmod: post._updatedAt` from the Sanity GROQ query.

### L-2 LOW — IndexNow not implemented

No IndexNow key exists. For a Sanity-backed site with active blog content, a Sanity webhook triggering IndexNow on document publish provides near-instant Bing indexation.

### L-3 LOW — x-powered-by: Next.js header exposed

**Fix:** Add `poweredByHeader: false` to `next.config.ts`.

### Note on FAQPage Schema

Google restricted FAQ rich results to government and healthcare sites in August 2023. FAQPage schema will NOT produce Google rich results for a commercial agency. However, it provides direct citation value in Perplexity, ChatGPT, and Gemini AI answers. Recommended if GEO is a priority.

### Implementation Architecture

## 5. Performance (Core Web Vitals)

**Score: 58 / 100** *(estimated — no CrUX field data available)*

| Metric | Estimated Value | Status |
|---|---|---|
| TTFB | ~150ms CDN hit / ~400ms+ on revalidation | Inconsistent |
| LCP | ~2.8s–4.5s | Needs Improvement / Poor |
| INP | ~200ms–400ms | Needs Improvement |
| CLS | ~0.05–0.15 | Good to Needs Improvement |
| Lighthouse Mobile (est.) | 55–72 | Needs Improvement |
| Lighthouse Desktop (est.) | 75–88 | Acceptable |

### Key Performance Issues

**LCP — GTM inline in `<head>` adds 200–600ms penalty.** The GTM initialization script runs synchronously in `<head>` before any resources are discovered. Moving it to just after `<body>` opens would reduce LCP by an estimated 0.2–0.5s.

**LCP — No `preconnect` for cdn.sanity.io.** The first Sanity CDN connection (DNS + TCP + TLS) adds 100–300ms to LCP image loading on cold connections. Add `<link rel="preconnect" href="https://cdn.sanity.io" crossorigin>` to `<head>`.

**LCP — Hero images lack `priority` prop.** The LCP candidate hero image is not marked `priority={true}` on Next.js `<Image>`, so it lacks `fetchPriority="high"` in the rendered HTML despite a `<link rel="preload">` being present.

**Cache misconfiguration.** `Cache-Control: public, max-age=0, must-revalidate` forces revalidation on every request. Adding `s-maxage=3600` targets Cloudflare edge cache while keeping `max-age=0` for browsers. Combined with `stale-while-revalidate=86400`, this eliminates the TTFB penalty for CDN-cached responses.

**CLS — Font metric mismatch.** Even with `display: swap`, if fallback font metrics differ from Manrope, text reflow causes layout shift on headings. Verify `adjustFontFallback: true` in `next/font` config (it's default but worth confirming).
